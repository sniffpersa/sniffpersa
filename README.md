## `whoami`

I'm a 15-year-old developer exploring the technical side of cybersecurity: understanding how software behaves, how systems fail, and how to build tools that make investigation more repeatable.

My approach is hands-on and research-driven: **inspect the system, form a hypothesis, test it in a controlled environment, document the evidence, and improve the implementation.**

Current interests include offensive security in authorized environments, reverse engineering, web security, OSINT, digital forensics, networking, and full-stack development.

- `mindset` — understand the mechanism, not just the symptom
- `workflow` — terminal-first, experimental, documentation-heavy
- `learning` — CTFs, security labs, source code, protocol analysis
- `principle` — test only systems I own or have explicit permission to assess

## `research_notes`

I aim to make security work understandable and reproducible, not just demonstrate that something works.

For future write-ups and lab notes, I use a structure like this:

1. **Context** — the system, challenge, or lab scope.
2. **Hypothesis** — what I expect to happen and why.
3. **Method** — the controlled test or analysis steps.
4. **Evidence** — logs, minimal examples, screenshots, or test output with sensitive data removed.
5. **Root cause** — the behavior or design decision behind the result.
6. **Mitigation** — how the issue can be prevented or detected.
7. **Limitations** — what was not tested and what remains uncertain.

CTF solutions, personal lab notes, and security research will be published when they are ready to be useful and safe to share.

## `principles`

- **Authorization first:** testing stays within owned systems, CTFs, labs, or explicitly authorized scopes.
- **Evidence over claims:** conclusions should be backed by reproducible observations.
- **Responsible disclosure:** suspected vulnerabilities should be reported privately through the appropriate channel.
- **Privacy by default:** avoid publishing real credentials, tokens, personal data, or unredacted forensic artifacts.
- **Keep learning:** fundamentals, careful experiments, and readable code matter more than collecting tools.
